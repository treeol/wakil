## R2. The release flow the repo actually uses

Found from the v0.8.11 release (no RELEASING doc; flow is in
`docs/plans/0.8.11.md` R2 and enforced by the workflows). Follow that flow:

- **Gates on the work branch**, then `git checkout master && git merge
  --ff-only work/0.8.12`; check `master` == branch head. v0.8.11 used
  exactly this: work head `1a4c660` → plan commit `671d57e` → notes commit
  `ee7dc14` → release commit `6d1a86a` on master; no merges in
  `v0.8.10..v0.8.11` (23 commits). The tagged commit is the release commit.
- **ONE release commit on master touching CHANGELOG.md only**
  (`git show --stat v0.8.11^{commit}` = `CHANGELOG.md | 18 ++++----`):
  `chore: release 0.8.12` (staged by explicit path, signed). It turns
  `[Unreleased]` into a fresh empty `[Unreleased]` plus `## [0.8.12] -
  <today, Europe/Zurich>` with an "Upgrading from 0.8.11, in short"
  paragraph. Checks: `scripts/release_notes.sh 0.8.12` prints it;
  `release_notes.sh 9.9.9` exits non-zero; heading is `## [0.8.12] - date`
  (the form `scripts/host_verify.sh` #11/#13 and `release_notes.sh` expect:
  heading exactly `## [X.Y.Z]` or `## [X.Y.Z] - date`, non-blank prose after
  it, first line starting with `#` when printed).
- **No version constant to bump.** `internal/buildinfo/buildinfo.go` has
  `Version = "dev"`; `.goreleaser.yaml` injects the tag via ldflags
  (`-X .../buildinfo.Version={{.Tag}}`); `cmd/wakil/version.go` prints it.
  `install.sh` carries only `HISN_VERSION` (now `0.6.5`); README pins no
  release. The only place v0.8.11 "bumped" anything is CHANGELOG.md (the
  release commit above). So for 0.8.12: CHANGELOG only, plus the already-
  committed `0.6.5` HISN bumps on the work branch.
- `.github/workflows/ci.yml` (push/PR to `master` + cron Mon 06:00): jobs
  test, lint, darwin-compile, goreleaser-snapshot, docker-build,
  sandbox-image-multiarch, bench-harness, hisn-integration, installer
  (4 distros). The goreleaser-snapshot job extracts the newest `## [` section
  and runs `release --snapshot --release-notes`.
- `.github/workflows/release.yml` triggers ONLY on pushed tag `v*`: validates
  the tag regex `^v[0-9]+\.[0-9]+\.[0-9]+(-...)?$`, requires the tagged commit
  to be an ancestor of master (compare `master...SHA` = `behind`/`identical`),
  builds and signs the sandbox image (ghcr, cosign keyless), runs goreleaser
  with `--release-notes` from `scripts/release_notes.sh <tag>` (fallback to
  git-generated notes if the CHANGELOG section is missing), then a package
  smoke test. Artifacts come only from this workflow. `checksums.txt` is
  produced by goreleaser and attested.
- **Tag**: signed annotated tag after the user writes "tag"
  (`git tag -s -a v0.8.12 -m "Wakil v0.8.12"` — v0.8.11 same form, tagger
  Valon Mamudi), `git tag -v v0.8.12`, push only the tag
  (`git push origin v0.8.12`, never `git push --tags`), wait for the Release
  workflow, report run URL, release page, artifacts, checksums present, and
  that `install.sh` at `releases/latest` resolves to v0.8.12 (read-only API
  check; do not install on this host).
