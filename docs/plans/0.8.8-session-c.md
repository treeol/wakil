### 1. OpenRouter credential rule — NOT "done in 0.6/0.8.6"

Current logic, internal/config/config.go:2726–2781 (quoted):

```go
active := c.ActiveEndpoint()
if IsOpenRouterHost(active.BaseURL) {          // (1) active OR endpoint
    ...hdr := c.AuthHeaderFor(active)
    if hdr == "" { return res, fmt.Errorf("no credential on endpoint %s", name) }
    return res, nil
}
if len(c.Endpoints) > 0 {                      // (2) FIRST sorted OR endpoint
    names sorted
    for _, name := range names {
        ep := c.Endpoints[name]
        if !IsOpenRouterHost(ep.BaseURL) { continue }
        hdr := c.AuthHeaderFor(ep)
        ...
        if hdr == "" { return res, fmt.Errorf("no credential on endpoint %s", name) }  // fails closed on the FIRST one
        return res, nil
    }
}
// (3) env var named by OpenRouterAPIKeyEnv
```

Differences from the required rule:
* (2) stops at the first sorted OR endpoint even when it has no credential
  and a later one has one. Required: first sorted OR endpoint THAT HAS a
  credential; fail closed only when OR endpoints exist and none has one.
* `AuthHeaderFor` falls back to the legacy global `api_key` for ANY endpoint.
  For a non-active OR endpoint that would send the global key (meant for the
  main, possibly local, route) to openrouter.ai. For non-active endpoints the
  resolver must use only the endpoint's own credential (`auth_header`, else
  `api_key_env`). The active endpoint keeps `AuthHeaderFor` (identical to what
  a main request sends). Not in the prompt; found while reading. Key routed to
  the wrong host, so included in block 1.
* Existing tests cover: active wins over env, active fail-closed, single
  non-active no-cred fail-closed, env only without OR endpoint, ilm-proxy not an
  OR endpoint, label does not leak. Missing: skip-no-credential-pick-later,
  all-no-credential fail-closed with several names, global api_key not used for
  non-active OR endpoint, api_key_env on non-active endpoint.
* `/mashura` already prints the chosen endpoint by name
  (mashura_command.go:150–154, `SourceLabel()` → `backend config (<name>)`);
  the missing-credential line also names it. Kept; tested via SourceLabel.

Touched: `Config.ResolveOpenRouterCredential`, a new unexported own-credential
helper, tests in openrouter_cred_test.go, docs/configuration.md
(`openrouter_api_key_env` row), CHANGELOG.

## Plan review (Mashūra round 1, three reviewers) — BLOCKING findings taken

The reviewers had no Go source; claims about Go behaviour are their recall and
are marked as such. Verified or reasoned by me where noted.

* B1 (block 3): a `--- PASS:` line alone is forgeable (a package-level `init()`
  in a non-test file can print it and `os.Exit(0)`). Taken. The check builds
  the test binary with `go test -c`, injects a per-check random nonce (generated
  at check time, after the agent finished) into the hidden test, which prints
  it on success; the check requires nonce + `--- PASS` + rc 0. Also statically
  rejects `func init(`, `os.Exit`, `syscall.Exit`, `go:linkname`, build
  constraints, `vendor/`, `go.work`, symlinks in the agent's non-test files.
  go.mod is RESTORED from the reference (not "fail if different"). The check
  runs with `GOFLAGS=-buildvcs=false GOWORK=off GOENV=off`, no `.git` in the
  copy. Self-test adds the "init prints PASS and exits" cheat. Residual:
  same-process code that reads the test source at runtime; stated in README.
* B2 (stale state): `prep_workdir` is called as `prep_workdir || …`, where
  `set -e` is off, so a failed `rm -rf` was ignored. Taken: after the wipe,
  assert the folder holds nothing but `.wakil/`, abort otherwise. Not taken:
  surviving agent child processes after a KILL (listed).
* B3 (`.wakil/` as cross-run channel): rule "harness never writes into a work
  folder's .wakil/" forbids filtering it. Taken in reduced form: read-only
  listing+hash of `.wakil/` before and after each run; a change prints a
  warning on stderr and is recorded in the README as a limit. Not taken:
  scrubbing it (conflicts with DO NOT ALTER).
* B4 (leak guard): taken. Pre-agent guard right after prep, fatal; no git
  command is ever run inside the work folder after the agent (agent-controlled
  `.git/config`); the post-run guard is file-existence only and turns the run
  into `error`/`leak-detected` with check.sh skipped. History check runs
  pre-agent only.
* Result JSON inside the agent-writable work folder (two reviewers: forged
  workdir/exit_reason; a symlink makes the host-side wakil clobber an arbitrary
  file): taken in block 9. The file lives under
  `${XDG_CACHE_HOME}/wakil-bench/run/` and is removed before each run; stubs
  take the folder from `WAKIL_HOST_WORKDIR`.
* Timeouts (block 5): 124/137 handling is moved BEFORE the sandbox-approval log
  grep (the transcript is agent-controlled text); both `-k` sites use
