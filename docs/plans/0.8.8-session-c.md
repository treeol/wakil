Facts established by running go in this sandbox (go1.26.11 in PATH, cached
toolchains go1.26.6 and go1.27.0 in the module cache) — they decide the design:

* `GOTOOLCHAIN=go1.26.6 GOPROXY=off go env GOVERSION` -> go1.26.6, rc 0

* `GOSUMDB=off` with a pinned cached toolchain -> rc 1, `verifying module:

## Design (decisions made, not open)

Check exit-code contract: **0 pass, 1 fail (the check ran and judged the agent's
work), 99 error (the check could not judge).** Any other status (2 syntax/unbound,
126/127 missing interpreter or python3, 137 killed...) is also "error": a check
that crashed did not judge anything. Only an explicit `exit 1` is "fail".
bench.sh maps it in `check_result_for_rc`; error rows get
`exit_reason=check-error`, the log carries a `check: ...` line, and the bench
stops with exit 1 (same class as leak/guard errors: the harness cannot judge,
and the same environment would repeat it on every following run).

1. Toolchain. `resolve_go` runs once at start (every mode except --help/arg
   errors; skipped when no selected task has `repo/go.mod`, so `--task steps`
   still works without Go): in the repo root, caller's environment, plus
   `GOPROXY=off` (the harness itself must not download either; deviation from
   "caller's environment" stated here), `go env GOVERSION` -> `go_toolchain`
   (first word; a `devel ...` version maps to `local`); also `go env GOMODCACHE
   GOCACHE GOPATH`. `with_go_env` exports them as `BENCH_GOTOOLCHAIN`,
   `BENCH_GOMODCACHE`, `BENCH_GOCACHE`, `BENCH_GOPATH` (+ `BENCH_BINARY_TIMEOUT`,
   `BENCH_KILL_GRACE`) inside the check/setup subshell only, never in the agent's
   environment. `gocheck_env` (one shared function, used by every Go check and
   setup.sh) sets `GOTOOLCHAIN=$BENCH_GOTOOLCHAIN`, `GOPROXY=off`, the fixed
   GOFLAGS/GOWORK/GOENV/CGO_ENABLED, restores the cache vars, unsets GOROOT
   GOTMPDIR GOEXPERIMENT GOARCH GOOS GOCACHEPROG; a missing
   `BENCH_GOTOOLCHAIN` is an error (checks are run by bench.sh).
2. Preflight (`preflight_go`, in `main` before the CSV exists and before any run;
   also at the start of `--self-test`): for every selected task that has a
   `setup.sh`, run it in a pristine copy of `repo/`; for every selected task whose
   check.sh sources gocheck.sh (add-flag, fix-test, rename), run that check.sh in a
   pristine copy of `repo/` with `BENCH_PREFLIGHT=1`. In that mode the check runs
   its real go commands (`go list -e -deps`, `go build`, hidden tests restored and
   compiled and run with `-run '^$'`) and stops with `gocheck_preflight_done`
   before it judges anything. Any failure -> one line on stderr, exit 1, no CSV:
   `bench: the Go checks cannot run: tasks need go >= <max go directive of the
   selected go.mod files>, found <resolved or installed version> — <first line of
   go's own error>`. "Found" = the resolved version, else
   `GOTOOLCHAIN=local go env GOVERSION`, else the `running go X` text of go's
   error, else `unknown`. `go` missing from PATH has its own line.
3. Result class inside a check. In gocheck.sh every go command that can fail goes
   through `gocheck_go` / `gocheck_blame`: on failure `gocheck_probe` repeats the
   task's go commands on a pristine copy of `repo/` (`go build ./...`, plus, when a
   hidden test package is known, hidden tests restored and `go test -run '^$'`,
   which also catches a noexec TMPDIR). Probe fails -> `gocheck_error` (exit 99);
   probe passes -> the agent's tree is to blame -> `gocheck_fail` (exit 1). Plain
   environment failures inside gocheck_prepare/gocheck_run (mktemp, tar copy, missing
   hidden/ tree, restoring hidden tests, unreadable task dir) become errors, not
   fails. Agent-judged failures (symlink, go.work, vendor, import allow-list, a
   test failure, a missing PASS line, old name present...) stay `exit 1`.
4. add-flag: the three runs of the agent's binary and the flag-after-string run go
   through `gocheck_bin` (`timeout -k $BENCH_KILL_GRACE $BENCH_BINARY_TIMEOUT`,
   stdin from a file, stdout/stderr into files so a stray child cannot hold a
   pipe). rc 124 or 137 -> `check: binary timed out`, exit 1. Every other
   non-zero status of the binary is the agent's behaviour (compared, not leaked
   as the check's own exit status: under `set -e` the binary's exit code 3 would
   otherwise become the check's status and read as "error"). `BENCH_BINARY_TIMEOUT`
   default 10, validated integer, like `BENCH_KILL_GRACE`.
