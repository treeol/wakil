# 0012 — hisn 0.4.0 session model

- **Status:** Accepted
- **Date:** 2026-11-07
- **Origin:** CHANGELOG 0.6.0, Phase A.

## Context

hisn 0.4.0 changed what a session is: it is a named place that several clients
join, with a lifecycle state, a per-client audit and an explicit stop. The
0.3.3 integration assumed none of it. Run against 0.4.0, every start timed out
after 10 s although the session was up: `hisn ls --json` moved to schema
`hisn-ls/v2` and reports `running` where 0.3.x said `live`, and Wakil's
readiness check accepted only `live`.

Everything below was measured against the released v0.4.0 binary (sha256
`b2fe06ce…`), not read from documentation:

- `--name` accepts letters, digits, `.`, `_`, `-`, no leading `.`; 64
  characters pass, 80 are refused.
- A name is unique per user. A **crashed** directory keeps its name reserved
  until `hisn ls --prune`; a directory ended with `hisn stop` releases it at
  once.
- `hisn stop` returns in about 100 ms, the supervisor is gone by then, the
  directory stays as `stopped`. On a session whose supervisor is already dead it
  still reports "stopped".
- `hisn ls --prune` archives and removes `stopped` and `crashed` directories
  and repairs the name index. `hisn kill` on one removes it too.
- The control socket accepts `client: {label, label_source, req_id}` on every
  request and refuses any other key (`uid` included) as `E_BAD_REQUEST`.
  `hisn exec` has `--client`; `grant`, `revoke`, `ls` and `inspect` have not.
- `hisn ls --json` has no `clients` array in 0.4.0 (hisn's changelog lists it
  for 0.4.1). Wakil parses it when present.

## Decision

- The minimum hisn version is 0.4.0, for the explicit backend and the default
  gate alike. There is no compatibility path for 0.3.x: a session model that
  works on two incompatible state vocabularies is two code paths to test.
- Wakil reads `hisn-ls/v1` and `hisn-ls/v2` and **refuses an unknown or missing
  schema**. A silent misparse of the state field is what broke 0.4.0, and an
  empty document would otherwise read as "every session vanished".
- Live means `running` (v2) or `live` (v1). Not live is not the same as dead:
  `stopped`, `crashed` and v1 `stale` are **ended**; `creating` and `stopping`
  are **transitional**. A transitional session is never called dead, never
  pruned and never ends a wait (`waitEnded`); a foreign one that holds our id
  or name is refused as in use, naming its state.
- Sessions are created with `--name wakil-<project key>-<chat id>`, shortened
  with a hash past 64 characters. The name is for humans and for other clients
  (attach, a second Wakil). **Every call Wakil makes after creation uses the
  id**: exec, grant, revoke, inspect, `ls --session`, stop and kill, the owner
  record, the instance token, and the argv the browser's ownership check
  matches against `ActiveSessionID`. A name can be released by a stop and taken
  by another session; an id held by our own supervisor cannot. Readiness checks
  once that the listing row with our id carries our name.
- Every control request carries `{label: "wakil@<hostname>", req_id:
  "<instance>.<session token>-<n>"}`: the request id is unique per Wakil
  instance **and** per session. The label is cut to 64 **bytes** on a rune
  boundary with invalid UTF-8 replaced, on the control socket and for
  `hisn exec --client` alike. Wakil never sends `uid`.
- Wakil ends a session with `hisn stop`, then waits on the supervisor handle as
  before. The `stopped` directory is left for hisn's audit; `hisn ls --prune`
  (Reconcile, and Start when a `crashed` leftover holds the name) archives it.
  A `crashed` directory left by our own failed start is pruned at once.
- A session that Wakil did not create and that is live or transitional and
  holds the chat's id or name is refused with `ErrSessionInUse`; Wakil never
  signals it.
- `hisn ls --prune` is **global for the user**: it archives and removes every
  provably dead directory (stopped or crashed), including other tools' stopped
  sessions, and repairs the name index. Wakil already ran it at every start
  before 0.4.0 (`Reconcile`), and 0.4.0 only adds the archive, so this is the
  accepted behaviour, not a new reach. Wakil itself prunes only on `Open`, on a
  failed start, when a `crashed` leftover holds the chat's id or name, and after
  its own session ended `crashed`. It does not prune after an ordinary stop:
  that directory is the audit record.
- `reconcileNamedLocked` still ends a named-profile session by signalling the
  supervisor Wakil spawned (pid and starttime), not with `hisn stop`: a named
  profile carries no instance token, so the supervisor identity is the only
  proof of ownership.

## Consequences

- hisn 0.3.x hosts are refused with a message naming 0.4.0 (explicit backend)
  or fall back to Docker (default gate).
- The audit trail on the hisn side attributes each action to a Wakil instance.
- A Wakil that dies without stopping leaves a `crashed` directory; the next
  Start or Reconcile prunes it, which archives its audit.
- Measured against the real binary, in addition to the list above:
  `hisn run --session-id <id> --name <n>` over a **stopped** directory of the
  same id and name replaces it and starts (`TestIntegrationRestartAfterStop`);
  `--session X` where X is an existing id resolves to that id first and only
  then as a name.
- Open items, not done here:
  - A Wakil that dies between spawning a named-profile supervisor and recording
    its pid leaves a record without the supervisor identity; the next Start
    refuses the chat id as in use until the directory is gone. Unchanged from
    0.5.x.
  - Parsing `members` and `lease` into behaviour (idle leases, a second client
    joining a seat) belongs with the remote-seat transport.
